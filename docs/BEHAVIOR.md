# คะแนนความประพฤติกลาง

เปิดใช้ผ่าน attendanceBehavior (Cloud Function, asia-southeast1) และ behavior.html

- คะแนนปัจจุบัน = 100 + ผลรวม delta ใน attendance_behavior ของนักเรียนและห้องนั้น รวมผู้บันทึกทุกคนและรายการเดิม ไม่ตัดเพดานคะแนนหรือสร้างรายการตั้งต้นทับประวัติ
- ครูต้องใช้ Google ที่ยืนยันอีเมลและมี profile active พร้อม attendanceRole teacher/admin หรือ legacy teacher ที่ใช้งานอยู่
- อ่านห้องตาม canRead; บันทึกรายคนต้องมี ACL active, canRead และ canBehavior การเป็น admin ไม่ให้สิทธิ์เขียนแทนครูโดยอัตโนมัติ
- ผู้ดูแลความประพฤติใช้ attendance_behavior_managers/{SHA256(lowercase(email))}: email, name, active สิทธิ์นี้แยกจาก school_users และไม่เปลี่ยนสิทธิ์งบประมาณ บัญชีกลาง หรือตารางสอน
- ผู้ดูแลความประพฤติเห็นห้องปัจจุบันที่ active ทั้งโรงเรียน และบันทึกได้ทั้งรายคนและกลุ่มไม่เกิน 100 คนต่อรายการ
- บัญชีผู้ดูแลที่ยังไม่เคย login ใช้ grant รอไว้ตามอีเมล เมื่อ Google ยืนยันอีเมลตรงกันจึงใช้งานได้ ถ้ามี central profile ที่ถูกระงับจะใช้งานไม่ได้
- ทุกการบันทึกต้องมีวันที่ เหตุผล คะแนนจำนวนเต็ม +/−1 ถึง 100 และนักเรียนที่มีอยู่ในห้องจริง
- กลุ่มบันทึกเป็น transaction เดียว ตรวจสิทธิ์ซ้ำภายใน transaction และบันทึก operation receipt ป้องกัน retry ซ้ำจาก requestId เดิม
- เหตุการณ์ใหม่เก็บ authorName และ groupId เพิ่มเติมใน ledger โดย backend ประวัติเก่าไม่มีชื่อจะแสดง “ครูผู้บันทึก” ไม่อ้างว่าเป็นชื่อผู้กำลังเปิดหน้า
- ไม่เปิดคะแนนหรือประวัติความประพฤติแก่ผู้ไม่เข้าสู่ระบบ และไม่แก้ Firestore Rules รวมของระบบอื่น
- รายงานเก่าใน reports.html ยังเป็นรายงานของครูผู้บันทึกตามระบบเดิม หน้าคะแนนกลางใช้ endpoint ใหม่
